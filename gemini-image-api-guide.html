01概览Overview

本服务提供与 Gemini 图像模型（Nano Banana 系列）一致的原生接口，用于文生图、图生图和改图。This service exposes native Gemini-image (Nano Banana family) endpoints for text-to-image, image-to-image and editing.

POST/v1beta/models/{model}:generateContent
POST/v1beta/models/{model}:streamGenerateContent
GET/v1beta/models

与官方唯一的区别：把 Base URL 指向 https://www.llmnex.com，把密钥换成我们为你签发的密钥。请求体、参数、响应结构与官方一致;只需把模型名改用下方我们的 16 个(分辨率写在后缀里),其余几乎零改动。The only difference from Google: point the Base URL at https://www.llmnex.com and use the key we issue you. Request body, parameters and response shape match the official API; just use one of our 16 model names below (resolution is in the suffix) — otherwise virtually no changes.

提示Note 图像模型固定返回图片，你无需设置 responseModalities。Image models always return an image — you do not need to set responseModalities.

03快速开始Quickstart

最小可用的一次文生图调用：A minimal text-to-image call:

bash 
curl https://www.llmnex.com/v1beta/models/gemini-3-pro-image-2k:generateContent \
  -H "x-goog-api-key: 你的密钥" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [{ "parts": [{ "text": "一只戴宇航头盔的柯基，工作室灯光" }] }]
  }'
bash 
curl https://www.llmnex.com/v1beta/models/gemini-3-pro-image-2k:generateContent \
  -H "x-goog-api-key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [{ "parts": [{ "text": "a corgi wearing an astronaut helmet, studio lighting" }] }]
  }'

返回体中的图片是 base64 编码的 PNG，位于 candidates[0].content.parts[0].inlineData.data。The image comes back as base64-encoded PNG at candidates[0].content.parts[0].inlineData.data.

04支持的模型Models

在路径里的 {model} 处填写模型名。名称末尾的 -preview 会被自动忽略。Put the model name in the {model} path segment. A trailing -preview is stripped automatically.

模型名 = 模型族 + 分辨率后缀。选哪个模型就等于选哪个分辨率——分辨率写在名称后缀里(见第 8 节),你不需要再单独传 imageSize。共 16 个模型:Model name = family + resolution suffix. Choosing a model = choosing the resolution — resolution lives in the suffix (see §8), you do not pass imageSize separately. 16 models total:

模型族可用模型(后缀)定位
gemini-3-pro-image-1k -2k -4k -c最高画质
gemini-3.1-flash-image-1k -2k -4k -c快速、均衡
gemini-2.5-flash-image-1k -2k -4k -c上一代快速
gemini-3.1-flash-lite-image-1k -2k -4k -c轻量最省(恒 1K)
FamilyModels (suffix)Positioning
gemini-3-pro-image-1k -2k -4k -cHighest quality
gemini-3.1-flash-image-1k -2k -4k -cFast, balanced
gemini-2.5-flash-image-1k -2k -4k -cPrevious-gen fast
gemini-3.1-flash-lite-image-1k -2k -4k -cLightweight (always 1K)

例:gemini-3-pro-image-2k、gemini-2.5-flash-image-1k。后缀:-1k→1K、-2k→2K、-4k→4K、-c→由你自传 imageSize 决定(默认 1K)。lite 族恒 1K,后缀再高也按 1K 出。用 GET /v1beta/models 拉当前完整列表。E.g. gemini-3-pro-image-2k, gemini-2.5-flash-image-1k. Suffix: -1k→1K, -2k→2K, -4k→4K, -c→set by your own imageSize (default 1K). The lite family is always 1K regardless of suffix. Use GET /v1beta/models for the full list.

09其他参数Other parameters

参数行为
seed整数。传入后透传给后端，用于尽量复现同类结果。
candidateCount可传，但本服务单次调用固定返回 1 张图。需要多张请多次调用。
temperature 等采样/文本参数会被接收但不影响图像生成（图像后端无对应能力），传了也不会报错。
ParameterBehavior
seedInteger, passed through to the backend to help reproduce similar results.
candidateCountAccepted, but each call always returns exactly 1 image. Call again for more.
temperature & other sampling/text paramsAccepted but have no effect on image generation (no backend equivalent); they won't cause errors.

10流式返回Streaming

建议使用一次性接口 generateContent，不建议流式。Prefer the one-shot generateContent — streaming is not recommended. 图像是整图一次性生成的，流式不会逐步、渐进地显示画面——它只会在生成结束时给你同一张完整图片，和非流式结果一模一样，反而多一层 SSE 解析开销。streamGenerateContent 仅为与 Gemini SDK 的流式调用保持兼容而保留。Images are generated all at once, so streaming does not render the picture progressively — it just hands you the same complete image at the end, identical to the non-streaming result, plus the overhead of parsing SSE. streamGenerateContent exists only for compatibility with Gemini SDK streaming calls.

如确需兼容流式客户端：把接口名换成 streamGenerateContent 即可走 SSE。因图像一次性生成完毕，只会返回单个数据块，其结构与 generateContent 完全一致。If you must support a streaming client: switch the method to streamGenerateContent for SSE. Because the image is produced in one shot, it returns a single chunk whose structure is identical to generateContent.

POST/v1beta/models/{model}:streamGenerateContent
SSE 
Content-Type: text/event-stream

data: {"candidates":[{"content":{"parts":[{"inlineData":{...}}]}}]}

12错误处理Errors

错误 body 为 new-api 结构:Error body uses the new-api shape: {"error":{"message":..,"type":..,"code":..}}(上游错误 type 为 upstream_error;平台自身错误如未知模型/未匹配渠道为 new_api_error)。4xx 保留具体原因,5xx 为通用文案。 (upstream errors carry type: upstream_error; platform errors like unknown-model carry new_api_error). 4xx keep the specific reason, 5xx are generic.

HTTPstatus含义 / 处理
400INVALID_ARGUMENT请求体有误（如缺 contents、图片 base64 非法、参考图超 14 张）。修正后重发。
401UNAUTHENTICATED密钥缺失或无效。
429RESOURCE_EXHAUSTED上游限流或后端过载(system under load)。指数退避后重试。
451INVALID_ARGUMENT内容审核:提示词/图片被判不安全(prompt_unsafe/image_unsafe)。终态,别重试——请修改内容。
503UNAVAILABLE上游临时不可用/池冷却/超时。稍后退避重试。
HTTPstatusMeaning / handling
400INVALID_ARGUMENTMalformed request (missing contents, invalid image base64, more than 14 reference images). Fix and resend.
401UNAUTHENTICATEDMissing or invalid key.
429RESOURCE_EXHAUSTEDUpstream rate limit or backend overload (system under load). Retry with exponential backoff.
451INVALID_ARGUMENTContent moderation: prompt/image deemed unsafe (prompt_unsafe/image_unsafe). Terminal — do not retry; change the content.
503UNAVAILABLEUpstream temporarily unavailable / pool cooldown / timeout. Back off and retry.

13完整示例Full examples

Python（requests）Python (requests)

python 
import requests, base64

resp = requests.post(
    "https://www.llmnex.com/v1beta/models/gemini-3-pro-image-2k:generateContent",
    headers={"x-goog-api-key": "你的密钥"},
    json={
        "contents": [{"parts": [{"text": "雪山湖泊，黄金时刻"}]}],
        "generationConfig": {"imageConfig": {"aspectRatio": "16:9"}},
    },
    timeout=300,
)
data = resp.json()["candidates"][0]["content"]["parts"][0]["inlineData"]["data"]
open("out.png", "wb").write(base64.b64decode(data))
